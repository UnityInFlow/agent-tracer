<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| network :4317 + :4318 → JVM | Both unauthenticated OTLP listeners (auth out of scope for v0.0.1) decode untrusted protobuf in one process. |
| env → boot config | Operator env (ports, sizes, ClickHouse creds) drives the lifecycle; migrations touch the schema at boot. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-12 | Denial of Service | Two listeners in one JVM sharing one bounded pipeline | mitigate | Single bounded `SpanWriter` channel + D-01 fail-fast (429 / RESOURCE_EXHAUSTED) shed load instead of buffering unbounded; both transports observe the SAME `BackpressureSignal`, so saturation is global and consistent. |
| T-03-13 | Tampering / availability | Migrations apply mid-serving or partially → first-request schema error | mitigate | D-04 migrate-then-serve: `runMigrations().getOrThrow()` runs to completion BEFORE any port opens; boot fails fast if the schema can't apply (Pitfall 7); proven by `TracerApplicationIT`. |
| T-03-14 | Denial of Service / data loss | Spans accepted during shutdown then dropped, or drain before ports close | mitigate | D-04 drain order: close ports FIRST, then `SpanWriter.drainAndClose()` flushes the in-flight buffer, then close the client; `TracerApplicationIT` asserts no loss on shutdown. |
| T-03-15 | Information Disclosure | Boot/shutdown logging leaking ClickHouse credentials or payloads | mitigate | Credentials sourced from env via `ClickHouseConfig` (no literals, T-02-02); logs counts/status only, never payloads or passwords (T-02-13). |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | No package-manager installs this plan; the otel-sdk/exporter test deps (added in 03-01) are first-party OpenTelemetry Maven Central artifacts (RESEARCH §Package Legitimacy Audit: all OK). No legitimacy checkpoint required. |
</threat_model>
