<objective>
Build the OTLP/HTTP-protobuf receiver: a Ktor `Route.otlpTraces(decoder, writer, signal, config)` extension serving `POST /v1/traces` on :4318. It reads the raw protobuf body, parses `ExportTraceServiceRequest`, calls the shared `OtlpDecoder` (03-01), sends each accepted span through `SpanWriter.send`, and returns the spec-conformant `ExportTraceServiceResponse`. It implements the three SC3 status behaviors: 200 (full/partial), 400 (undecodable body), 429+Retry-After (saturation, fail-fast).

Purpose: INGEST-01 — the standard OTLP/HTTP transport. This is the half of the receiver a stock `OtlpHttpSpanExporter` posts to. Decode + response logic is reused from 03-01, so this plan is pure HTTP framing + status mapping + the DoS body-size guard.

Output: `ingest/OtlpHttpRoutes.kt` + `OtlpHttpRoutesTest.kt` (in-process `ktor-server-test-host` conformance tests, no socket, no Docker).
</objective>

    1. FIRST statement: `if (signal.isSaturated) { call.response.headers.append(HttpHeaders.RetryAfter, config.retryAfterSeconds.toString()); call.respondBytes(ContentType("application","x-protobuf"), HttpStatusCode.TooManyRequests) { ByteArray(0) }; return@post }` (D-01 fail-fast; do not read the body).

    5. `val result = decoder.decode(request)`.
    6. `result.accepted.forEach { writer.send(it.span, it.context) }` — `send` is suspend and the Ktor handler is already suspend (no bridge needed; it may briefly suspend on the bounded buffer, acceptable per D-01).
    7. `val response = OtlpResponses.buildResponse(result)` then `call.respondBytes(ContentType("application","x-protobuf"), HttpStatusCode.OK) { response.toByteArray() }`.
