Import `io.grpc.Status` aliased (e.g. `import io.grpc.Status as GrpcStatus`) to avoid collision with `io.opentelemetry.proto.trace.v1.Status` used inside the decoder (PATTERNS type-collision guard).
    Override `export(request: ExportTraceServiceRequest, responseObserver: StreamObserver<ExportTraceServiceResponse>)`:
    1. FIRST: `if (signal.isSaturated) { responseObserver.onError(GrpcStatus.RESOURCE_EXHAUSTED.withDescription("ingest pipeline saturated; retry with backoff").asRuntimeException()); return }` (D-01 fail-fast; no decode). KDoc that D-01 deliberately uses RESOURCE_EXHAUSTED over the spec's UNAVAILABLE — both are retryable in the OTel SDK/Collector (Pitfall 6).
    2. Bridge callback → suspend: `scope.launch { try { val result = decoder.decode(request); result.accepted.forEach { writer.send(it.span, it.context) }; responseObserver.onNext(OtlpResponses.buildResponse(result)); responseObserver.onCompleted() } catch (e: Exception) { responseObserver.onError(GrpcStatus.INTERNAL.withDescription(e.message).asRuntimeException()) } }`.
    NEVER `runBlocking`/`Thread.sleep`/raw thread inside `export` (CLAUDE.md ban + Pitfall 2 — blocking a grpc-netty event-loop thread stalls the transport). The undecodable-body case is handled by gRPC's own protobuf marshaller BEFORE `export` is invoked (it raises INVALID_ARGUMENT automatically), so there is no manual parse-failure branch — KDoc this (A3). `val`-only, no `!!`. Note in KDoc that the standalone `io.grpc.Server` (built in 03-04) must set `.maxInboundMessageSize(ReceiverConfig.grpcMaxInboundBytes)` so SC2's >4 MB spans are accepted (default gRPC cap is 4 MiB).
