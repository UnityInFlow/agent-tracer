<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| curl/client -> :8080 query API | NEW untrusted HTTP surface. Query params + the `{id}` path param are untrusted input crossing into the ClickHouse-backed read path. Auth is OUT of scope (CONTEXT); model the threats and note where auth would later mitigate. |
| :8080 JSON server vs :4318 protobuf server | Two embeddedServers in one JVM; the JSON ContentNegotiation plugin must NOT touch the protobuf OTLP Application. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-10 | Tampering | `{id}` path param into getTraceById | mitigate | `{id}` is passed only as a client-v2 `{name:Type}` placeholder to the repository (T-02-06); the query layer builds no SQL. Blank/missing id -> 400 before any read. |
| T-04-11 | Tampering | filter/cost/date query params | mitigate | Validated + bounded in RunListMapper (Plan 02, T-04-03/T-04-04) before reaching the paginated listRuns; bound as placeholders in storage. |
| T-04-12 | Information Disclosure | error responses on :8080 | mitigate | 400/404/500 return short generic messages only; no stack trace, SQL, or DB internals echoed. Repository logs failures server-side (not to the client). |
| T-04-13 | DoS | unbounded result / large limit on /api/runs | mitigate | limit clamped <= 500 + offset floored (Plan 02 paging); response is a bounded page. Phase-2 14-day TTL bounds per-run DAG size. |
| T-04-14 | Spoofing | unauthenticated query + OTLP surfaces | accept (descoped) | Auth explicitly OUT of scope for Phase 4 (CONTEXT). A later milestone adds the STACK.md transport-agnostic token validator as a gRPC ServerInterceptor + Ktor Authentication plugin over both :8080 and the OTLP ports. Documented, not planned here. |
| T-04-15 | Denial/leak | :8080 server not drained on SIGTERM (port leak) | mitigate | queryServer added to RunningReceivers + stopped in shutdown() alongside ktor.stop (Pitfall 3); `docker compose down` releases :8080 cleanly. |
| T-04-SC | Tampering | dependency installs | mitigate | No new packages (consumes Plan-01 JSON deps); no `[ASSUMED]`/`[SUS]` installs; no checkpoint required. |
</threat_model>
